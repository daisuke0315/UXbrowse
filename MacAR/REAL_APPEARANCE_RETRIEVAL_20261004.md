# 登録実写の選び方：3条件比較（2026-10-04）

## 結論

今回の対象では、**3DGSの方向候補を残し、その方向と整合する登録実写を見た目で選ぶ `gs-real` を推奨**する。角度が近い写真が、必ずしも局所照合に適した写真とは限らないため、実写cropのDINO特徴とパッチ配置で選び直す。

新写真の成功率は現行と同じ11/12で、万能な改善ではない。一方、登録写真のRC姿勢との位置差の大きい例を改善し、新写真でも支持点が増える例があった。実写だけの直接検索は一部で速いが、IMG_2593/2594で失敗した。独立した3DGS方向制約は残す方が今回の用途には適する。

以下は採用前のオフライン比較の履歴。比較実施時には本番の既定を変更していなかった。その後ユーザーの指示で、登録実写モードの既定へ `gs-real` を採用した。[現行仕様](docs/real-appearance-retrieval.md)。ライブ追跡・CT表示の判定は維持。カメラ実機・動き・遮蔽・CTマーカーの物理誤差は未評価。

## 比較したもの

| 条件 | 粗い方向／照合写真の選び方 |
| --- | --- |
| `gs-angle`（現行） | 3DGS/DINO Top3 → 各方向にRC姿勢が近い実写を2枚ずつ |
| `real-direct` | 実写cropのDINO類似度Top10 → パッチ配置で再順位付け → 上位6実写 |
| `gs-real`（今回の推奨） | 現行3DGS Top3 → 各方向にRC回転差55°以内の実写集合 → DINO Top10・パッチ配置 → 各2実写、重複なし |

全条件で実際に6枚を照合した。実写直接条件だけは、独立したライブ対GS方向制約がない。方向QCの比較先は、選んだ実写に姿勢が最も近い既存GS viewとする。この条件差があるため、直接検索の高速性だけで置換を判断しない。

共通の流れ：同じ検出ROI・DINO query特徴 → 同じALIKED query特徴 → LightGlue → Fundamental行列RANSAC → 同じ三角測量済みXYZ → PnP → 領域別採点・既存QC。AIの再学習、XYZの再生成、QC緩和は行っていない。

## 結果

各条件2回。2回とも全24枚でPASS/FAIL、選択参照、対応数、inlier数が一致した。表の成功数は独立写真数、時間と誤差の中央値は2回分から求める。繰り返しを24枚の独立写真として扱わない。

| 評価 | 現行 `gs-angle` | 実写直接 `real-direct` | 方向制約＋実写 `gs-real` |
| --- | ---: | ---: | ---: |
| 新写真12枚：QC PASS | 11/12 | 10/12 | 11/12 |
| 新写真：処理成分合計中央値 | 2.24秒 | 1.74秒 | 2.17秒 |
| 新写真PASSのinlier中央値 | 180 | 164 | 188 |
| 登録写真12枚：QC PASS | 12/12 | 12/12 | 12/12 |
| 登録写真：RC姿勢との評価基準内 | 11/12 | 12/12 | 12/12 |
| 登録写真：RC回転差中央値 | 0.156° | 0.068° | 0.119° |
| 登録写真：RC中心位置差中央値 | 1.87 | 0.96 | 1.43 |
| 登録写真：RC中心位置差最大 | 17.96 | 4.59 | 4.59 |
| 登録写真：処理成分合計中央値 | 1.69秒 | 1.83秒 | 1.79秒 |

位置差の単位は **map units**。CTマーカーで測ったmm誤差ではない。登録写真の評価基準は、RC回転差5°以内かつ中心位置差が対象の頑健な対角長284.29の5%以内（14.21 map units）。これは今回の評価用基準で、ライブQCの変更ではない。

今回の144試行でAMBIGUOUSは0件。新写真でPASSした結果はすべて事前記録の面方向区間内。ただし区間幅は90°で、正確なカメラ位置・方向の正解ではない。登録写真の現行00542.pngはQCを通るがRC位置差の評価範囲外だった。**QC PASSと位置精度は別の評価**である。

## 何が効いたか／残った失敗

| 写真 | 現行 | 方向制約＋実写検索 | 解釈 |
| --- | --- | --- | --- |
| IMG_2592 | PASS・39 inliers | PASS・156 inliers | 同じ方向候補でも、照合に適した実写へ変わった |
| IMG_2593 | PASS・50 inliers | PASS・137 inliers | 対象内の支持領域も11→16領域へ増加。実写直接検索は8点でFAIL |
| IMG_2594 | PASS・228 inliers | PASS・232 inliers | 現行も良好。実写直接検索は方向QC不一致でFAIL |
| IMG_2598 | FAIL・20 inliers | FAIL・5 inliers | 方向制約を維持した検索では解決せず。実写直接検索は126点でPASS |
| 登録00542.png | PASS・188 inliers・RC中心差17.96 | PASS・629 inliers・RC中心差1.31 | 参照が00594→00423へ変わり、RC回転差も1.67°→0.11° |

inlier数の増加だけを精度の証明としない。IMG_2592ではinlierが増えても、全画像に対する凸包面積は小さくなっている。今回の姿勢候補採点は共通8×8対象ROI内の領域支持を使い、点の密集による水増しを抑える。

IMG_2598は現行も推奨条件も、点の集中と粗い方向との不整合でFAIL。直接検索では別の実写が見つかるため、**GS側の候補制約で有効な実写を落とす可能性が残る**。ただし方向制約を単純に外すと2593/2594が失敗する。失敗時だけ独立した実写検索を使う案には価値があるが、その統合方式は今回実装・評価していない。

## 速度の内訳

新写真の中央値：

| 工程 | 現行 | 実写直接 | 方向制約＋実写 |
| --- | ---: | ---: | ---: |
| 候補選択（DINO特徴生成後） | 88 ms | 106 ms | 374 ms |
| 6参照の局所照合・XYZ・PnP/QC等 | 1513 ms | 1004 ms | 1287 ms |

共通準備の工程別中央値は、ROI検出100 ms、DINO query20 ms、ALIKED query258 ms。ただし工程別中央値の和は合計中央値と一致しない。

推奨条件は局所照合を短縮する一方、各GS候補の実写パッチ再順位付けが約350〜370 msと重い。新写真の合計は約3%短縮に留まり、登録写真では約6%遅い。**今回の利点は候補の質であって、一律の高速化ではない。** 次の最適化対象は、3方向で重複する実写のパッチ評価を再利用すること。

時間は同期したMPS処理成分の合計。モデル初期化・索引ロード・初回索引生成を除外し、カメラ・ブラウザ・CT描画・ライブ競合は含めない。共通ROI/DINO/ALIKED生成は1回、条件順は交替、参照ロードcacheは各条件でクリアした。モデルwarmupは行ったが、形状別の初回計算やcacheの影響は完全には除けず、2回の測定だけで小さな速度差を断定しない。

## 評価の限界

- 新写真はIMG_2589〜2600の12枚。カメラ内部パラメータは近似HFOV72°・歪み0。物理位置の真値はない。
- 登録写真12枚は以前の比較でRC方向から事前選定。自身と±5フレームを全条件で参照から除外したが、地図作成に使った連続撮影写真であり独立holdoutではない。RC姿勢は推定基準で、外部計測真値ではない。
- 実写直接検索の登録写真Top1方向差中央値2.92°、Top5/10最小差2.69°/2.54°、全12枚がTop1で10°以内。近接登録写真との一致なので、未知写真・ライブでも同じ性能になる証拠ではない。
- 全条件は最大6枚の全候補評価で、早期終了・Top10追加探索・XYZ-only再試行・明度再試行を無効にした。候補選択だけを比較するための条件で、通常ライブの所要時間そのものではない。
- 元のアルファ条件の128 GS view、同じstage48地図、保存済み620実写DINO索引を使用。地図・コードSHA等を記録し、索引の名前・形状と3枚の再抽出特徴／mask一致を検査。原画像全枚の再監査ではない。
- 1対象・少数写真。医療ナビゲーション精度、患者移動、創部遮蔽、実機周回追跡の改善は今回の結果だけでは主張しない。
