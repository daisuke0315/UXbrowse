# 任意領域の画像遮蔽検証（現行仕様）

創部付近の外観情報が失われた場合のローカライズ耐性とCT表示ずれを検証する。切開による変形・内部露出・患者運動そのものを再現するものではない。

1. 写真またはライブでPASSさせ、CT測定画面で画像を固定する。
2. 「任意領域の画像遮蔽」を選び、左画像を3点以上の多角形で囲む。一回の試験につき一領域。頂点は画像画素座標で保持し、拡大・移動しても位置は変えない。
3. 「遮蔽照合の参照」を選ぶ。既定の「粗検索からやり直す」は、元画像と灰色（RGB 75）の遮蔽画像を各々、対象物検出→粗検索→局所照合→XYZ取得→PnP→QCで処理する。元PASSの姿勢・参照view・対応点を渡さず、画像別にROIと候補を取り直す。「元PASS時の参照view／登録写真を固定」は、元PASSで採用した3DGS view群、または登録実写のファイル名を両試行で共通にし、view検索・登録実写の再選択を行わない。ROI検出・ALIKED抽出・LightGlue・XYZ取得・PnP・QCは各画像で改めて実行する。対応点やPnP解を流用せず、回転・位置はともに再推定する。登録実写では元PASS姿勢を既存の向き差QCの比較基準に使うが、PnPの回転を固定したり初期解として与えたりしない。固定参照を特定できない・利用できない場合はエラーとし、全体検索へ黙って切り替えない。追跡の`POSE_LANDMARKS`は写真/viewではないためこの試験には使えず、全体再照合でPASS後に固定し直す。同じ特徴数・QC条件を用い、登録実写では両試行とも全候補を処理して早期終了しない。通常照合より長くなる場合がある。
4. 遮蔽境界の人工特徴を使わないよう、遮蔽領域と周囲の安全帯の対応も除外する。参照画像・XYZ地図は変更しない。
5. 前後の候補、対応数、採用点、処理時間、QC理由を比較する。両方PASSの場合だけ遮蔽後の姿勢を測定画面へ反映する。FAIL/ERRORでは直前の固定姿勢を維持し、不採用を明示する。
6. 「遮蔽後の姿勢でずれを測る」から元画像とCTのマーカーを指定する。測定表示は未遮蔽画像なので、遮蔽されたマーカーも評価できる。元の姿勢との差・再投影誤差はCTとの真値誤差ではない。

登録実写ALIKED・3DGSの両方式に対応する。既存の「面対応点の除外」は別試験として保持する（入力RGBは変更せず元PASS参照を固定できる）。画像遮蔽はRGBを実際に変更する試験であり、粗検索の再実行は上記の選択に従う。結果・JSONLには参照選択方針と固定参照名を残す。検証用QCはライブ設定へ反映しない。処理状態・seed・診断はロック下で復元し、追跡へ混入させない。

### 参照固定で一面だけの支持を調べる（2026-10-15）

元画像でPASSして固定→「任意領域の画像遮蔽」→「元PASS時の参照view／登録写真を固定」→他の面を含む領域を囲み、一面を残す→「参照を固定して遮蔽前後を照合」。これは粗検索の失敗を切り離すための条件付き試験で、遮蔽下での独立ローカライズ成功率とは区別する。ROI検出も各画像で行うため、遮蔽による検出失敗は残る。平面支持でもQCは自動緩和しない。点不足・分布不足・姿勢の曖昧性などのFAIL理由を確認し、両方PASSの場合だけ遮蔽後姿勢でCT測定へ進む。

確認手順：両方式・写真/カメラ固定画像で参照名が前後とも元PASSと一致すること、局所対応・姿勢は再計算されること、欠損参照の明示エラー、FAIL時の元姿勢維持、測定画面への復帰を確認する。

2026-10-15確認：新規テストが参照固定未実装で失敗することを確認後、実装して全512自動テスト成功。固定参照だけを用いた前後2回の照合、新しいquery workspace、登録実写の既存検証経路への接続、両方式×写真/カメラ入力の制御、未取得参照の拒否、比較結果への参照方針・名前の保存を確認。JavaScriptの構文検査も成功。合成画像・合成PnPのローカル確認サーバーを使い、ブラウザで固定参照選択→4頂点遮蔽→比較PASS表示→「遮蔽後の姿勢でずれを測る」からCT重畳へ復帰する操作を確認した。[確認画面](../../data/MacAR/output_fixed_reference_occlusion_20261015/ui.png)。この画面のPASSは合成結果であり、実データの成功率・平面姿勢精度の検証ではない。iPhone実機・実写真での新モードの精度は未確認。

## 遮蔽・小対象の検出再検索（2026-10-05）

以下のview独立検索の説明と実測は「粗検索からやり直す」条件。参照固定条件でもROI対象検出は各画像で実行するが、view・登録写真の選択は再実行しない。

全体画像のDINOパッチ対象検出が成功すれば従来のROIをそのまま使う。失敗時だけ、画像幅・高さの60%を切り出した重なりのある四隅の4領域を各長辺448px相当で検索する。前景類似度0.55、背景との差0.02、連結5パッチ以上の条件は維持する。候補は前景と背景の平均類似度差、パッチ数の順で選び、bboxと前景maskを元画像の座標へ戻す。見えている部分からROIを作る方式であり、遮蔽された形状の復元ではない。

追加検索は最大4回で、全体検出が成功した画像には追加推論しない。遮蔽前のbbox・姿勢・viewを流用せず、元画像と遮蔽画像は同一条件で独立検索する。ALIKED、LightGlue、XYZ、PnP/QCは変更しない。背景の誤検出・候補選択の失敗は残り得る。検出失敗時の追加遅延は実測し、全条件での改善を保証しない。

検証結果とJSONLには対象検出の試行数・採用スケール・検出理由を含める。前段で停止した場合は対象領域なし／特徴不足／実写候補なし等の停止理由を、採用0点という結果より先に表示する。

確認手順：同じ写真・同じ保存済み遮蔽多角形で旧全体検出と新検出のROI・候補・PnP結果・時間を比較する。実機では初期探索、遮蔽後の独立探索、背景しかないフレームの棄却を確認する。保存済み地図・参照画像は変更しない。
