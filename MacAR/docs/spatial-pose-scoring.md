# 登録実写の姿勢候補の採点（2026-10-04）

現行の登録実写ALIKED経路では、同じ検索画像・同じ対象cropを8×8に分割し、各領域を最大1票として候補を採点する。候補ごとのinlier範囲で区画を作り直さない。密集したinlier数を優先していた方式は過去仕様とする。

各領域のinlier再投影誤差の中央値を `e`、現在のPnP RANSAC閾値を `t` として、票は `max(0, 1-(e/t)^2)`。候補の点数は全領域の票の合計。満票なら64点。誤差は検索画像の元ピクセル単位で計算する。領域ごとの中央値の平均も診断に記録する。点数が同じ場合は占有領域数、領域平均誤差の順に比較し、生のinlier数を順位の決定に使わない。

既存QCを通った候補を優先し、その中を上記点数で選ぶ。早期終了時の最良候補と、最良候補の70%以上の支持がある別姿勢の競合判定も同じ点数を使う。早期終了の必要点数・比率・誤差・3D分布・crop被覆率・独立した実写2枚の姿勢合意と、最終曖昧性の姿勢差閾値は維持する。QC失敗した候補の点数が高くても採用しない。

全点によるPnP RANSACとLM、対応点作成、QC、3DGS粗検索、照合と追跡の並行処理は維持する。変更対象は登録実写経路の候補間評価。比較用の3DGS仮想画像経路や、候補比較を行わない単独PnPは変更しない。

## 検証と制約

- 自動テストで密集点の水増し、広域支持、誤差による順位、共通crop、QC優先、早期終了・競合判定の整合性を確認する。
- 実写比較は同じ特徴点・同じ候補を最後まで照合して旧採点と新採点を比較する。早期終了による候補集合の違いと採点の違いを混同しない。既存の検証写真12枚と、RC推定姿勢のある登録写真12枚を対象にする。
- 8×8と中央値は初期の設計判断で、最適性を立証した設定ではない。区画境界・crop変動、1点だけの領域、似た面の誤対応、正しい候補の欠落を完全には解決しない。PnP内部で密集点が仮説生成に影響することも残る。
- RC姿勢はSfM推定値であり物理真値ではない。検証写真の面方向とQCはCTの物理位置精度を保証しない。
- 実行中のアプリへの反映にはPythonプロセスの再起動が必要。実カメラでは回り込み時の面の選択・誤選択・FAIL増加を確認する。
