# ライブ追跡・送出とMPR更新の分離（2026-10-16）

現行仕様：MacARブラウザの登録実写・3DGSライブの追跡上限は30 fps（実効値の保証ではない）。カメラ/AF・対応生成・PnP/QCは維持する。

追跡回数が増えただけで周期探索負荷が倍増しないよう、ブラウザの周期条件は従来の15 fps上限換算の時間を保つ。標準の再探索150→300フレーム、視点補充の安全確認900→1800、厳格設定45→90、周期補充30→60。点数/残差/分布などの品質ゲートと動的補充条件は変えない。CLI単独の設定は変更しない。

1. 最新画像とその追跡姿勢・対応点を、MPR完成を待たず送出する。
2. MPRは同時1件。空いたら最新PASSと断面設定をsnapshotし、待機ジョブを積まない。ライブ用ワーカーはnative RGBA texture（既定192角）と同じ断面のモデル座標4隅・中心・法線を生成し、画面全体へのwarpをしない。
3. 断面4隅を最新PnP姿勢/Kから同次clip座標へ投影し、ブラウザWebGLで透視補正して既存MPR canvasへ描画する。古い画面画素を最新映像へそのまま貼らない。
4. 次の完成まで断面内容/方向は生成時点のままだが、表示位置は最新姿勢に追従する。MPR平面・前景マスク・模擬モデルの切断は実際に表示中の断面に統一する。表示済みslice revision/request IDを要求中の値と区別する。
5. 既存の1秒上限を超えた断面、世代/barrierの古い結果、カメラ後方の平面、ロスト姿勢は非表示。初回生成中も最新映像を送る。WebGLが使えない場合はMPRだけ非表示にして理由を表示する。
6. 写真・固定検証・強制描画は従来の画像座標PNGと逆投影を維持する。固定時には同じ画像/姿勢からMPRを再生成し、ライブtextureで計測しない。

追跡実行・MPR完成・パケット送出の回数を時間窓で集計し、実効fps、MPR年齢/source IDをメタデータとJSONLへ保存する。0.5秒ごとのログサンプル数や計算時間の逆数を実効fpsにしない。

制約：急な視点変更直後は新しい断面内容の再生成を待つ。その間は前の世界平面を正しく投影する。背景照合/GSのGPU競合、JPEG転送、誤照合/ロストは別問題。CT位置精度・30 fps達成は未保証。

検証：遅いMPRでも最新画像/姿勢を送る、同時1件、最新姿勢への4隅投影、期限/ロスト/reset棄却、固定測定の厳密対応、texture上下と透視補正を自動/ブラウザで確認する。実機では周回時の追跡/送出/MPR fps・年齢・ロスト率を同条件比較する。実施結果は完了時に追記する。

実施結果：全520自動テスト、JS構文検査成功。既存CTの描画部分は同一既知姿勢で16.46→4.21ms（中央値、画面warpをGPUへ移動）。120ms待ちを注入した合成ライブではMPR約6.7fpsの間も追跡呼び出し/送出約24.8fpsを確認。ブラウザでCTパターンの上下/透視投影と固定測定↔ライブ移行を確認。実機のfps・位置精度は未確認。[条件・詳細・合成画面](../../data/MacAR/output_live_mpr_20261016/README.md)。`pipeline_fps.tracking`は追跡処理の呼び出し頻度で、PASS頻度ではない。JSONLのstatusと合わせて評価する。
