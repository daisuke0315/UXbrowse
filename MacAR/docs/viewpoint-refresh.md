# 視点と新領域による対応点補充

2026-10-22現行：背景モードは有限待機付きの継続近傍補充。同一視点の維持照合に加え、4°の物体相対方向変化から先行起動し、新投影区画・予測方向も優先する。新視点は通常の稼働率待機と登録実写contextの4秒制限を待たず、100ms以内の鮮明画像を使う。[先行補充の条件・制約](regional-replenishment.md)・[資源回収と撮影日時の扱い](live-refresh-recovery.md)。以下は10/4の変更履歴であり、「同一視点で通常補充を停止」は現行の停止条件ではない。

## 2026-10-04の変更履歴（以下は当時の仕様・試験）

登録実写・3DGS仮想画像の共通ライブ追跡で、バックグラウンド補充を必要時の起動へ変更する。安定した同一視点ではALIKEDを繰り返さない。既存の点不足・分布不足・残差増加・急変・ロスト復帰・定期全体確認は維持する。

## 主条件

1. 最後に補充または既存点の再確認が現在画像でQCを通った姿勢から、物体中心→カメラ中心の方向が12°以上変わったら補充する。カメラの回転行列だけで発火させない。既存 `--tracking-replenish-angle` はこの方向差の閾値とする。
2. 地図の固定8×8×8区画を最大512個の実在ランドマークで代表し、カメラ前方かつ画面内に投影される区画を比較する。区画はXYZの2〜98パーセンタイル範囲を基準に作る。前回確認時になかった区画が4個以上、かつ現在の投影区画の10%以上なら補充する。境界の揺れを抑えるため、基準は画面の外側2%まで、現在は内側2%に投影される区画を使う。これは新しく画面内に入った地図領域の予測で、面の可視性・遮蔽の真値ではない。descriptor抽出を必要としない軽い判定。閾値は初期のヒューリスティック。
3. 現在の見る方向の変化が3°以上あり、既存の制限付き運動予測で8°以上へ進む場合は先行補充する。回転だけの予測では発火しない。カメラ位置の移動だけでも既存の運動予測を生成できるようにする。予測姿勢を表示・PnP観測へ使わない。

現在姿勢は処理フレームのLK/PnP/QCを通したもののみ使用する。同時1探索、処理時間を使う待機・失敗backoff・前景負荷優先を維持する。点支持が弱い場合の先行補充・高速復帰は従来条件を維持する。新しい視点だけを理由に、追跡支持が強いまま連続失敗から全体探索へ昇格させない。定期安全確認は角度や新区画がなくても可能。

補充成功・既存点の現在QC確認・初期姿勢の採用時に基準を更新する。失敗した検索の開始/終了だけでは基準を更新しない。resetで基準を破棄する。画像サイズや内部パラメータが変わった場合は投影区画の基準を再作成し、画像座標条件の違いを新領域と数えない。

## 処理フロー

`LK → 現在PnP/QC → 方向差・新投影区画・点支持判定 → 空き/待機/負荷確認 → 検索画像選択 → 補充ワーカー`

補充ワーカーは従来通り。登録実写は現在姿勢からXYZ候補を投影してALIKED・局所descriptor照合・独立PnP/QC。仮想画像は近傍view/LightGlue。検出直後の点を並行LKし、現在画像へ到達してQCを通った対応だけを追跡集合へ統合する。PnP/QC閾値と点数上限を緩和しない。coverageモードも同じ幾何条件を使い、比較用intervalモードの周期設定は保持する。

## 検証

自動テスト：静止・同一カメラ中心のロールでは通常補充しない、カメラ回転が同じでも回り込みで発火する、新規投影区画・小変化・成功時の基準更新・失敗時の維持・reset・画像条件変更・点不足・定期全体確認・同時1探索・前景負荷・予測方向の制限を確認する。

再現試験：保存済みRC姿勢と地図で旧条件と新条件の発火を比較し、固定カメラ位置のロール、同じ姿勢、新しい方向、画角へ入る領域を試す。これはスケジューラの試験で、実カメラの照合成功や3DGS/CTの物理精度を証明しない。再起動後、同一視点での補充抑制と回り込み時の点補充・ロスト頻度を確認する。実行中アプリを自動再起動しない。
