# 写真の解析入力統一（2026-10-21 現行仕様）

元写真の解像度を表示・CT投影・測定用に保持し、照合の画像特徴を計算する入力だけを小さくする。
登録実写ALIKEDと3DGS仮想参照の両モードで共通にする。ライブ動画の設定・追跡方式は変更しない。

## フローと座標契約

1. EXIF方向を反映した元写真を保持する。既存の歪み補正とカメラ内部パラメータを使用する。
2. 写真用retrieval indexに幅1280pxの上限を設定する。大きい画像だけINTER_AREAで縦横比を維持して縮小し、DINO対象検出・粗検索・パッチ再順位付けへ渡す。小さい画像は拡大しない。
3. 正規化bboxを元写真へ適用し、ALIKEDは元写真の対象cropから抽出する。既定の抽出長辺は1024px。比較・細部確認用に1600／2048pxの明示選択を残す。
4. 既存の抽出器の座標復元とcropのオフセットで元写真UVへ戻し、LightGlue・幾何検証・XYZ取得・PnP/QCへ渡す。3DGSの参照特徴は既存の同サイズ正規化を使用し、登録実写の保存特徴・XYZは変更しない。
5. PnPのK・歪み・画素閾値・QC・CT逆投影は元写真座標のまま。画像全体を1280へ縮小してPnPする方式ではなく、4px等の許容範囲を実質的に緩めない。

全体検索と参照固定検証のROI検出は、同じ解析入力の縮小規則を使う。面除外・画像遮蔽の2D多角形は元写真座標で保持する。正規化bbox/maskの契約は維持し、粗検索用の画素座標をPnP・測定へ混入させない。
写真初回・再照合・Top-3失敗時Top-10拡張に適用する。既存のキャッシュ解放と候補拡張予算は維持する。背景ワーカーの実行方式、地図、参照RGB、XYZ、マッチング/QCの閾値は変更しない。

## 設計根拠・制約

[変更前の3条件比較](../../data/MacAR/output_photo_input_comparison_20261021/README.md)では、粗検索1280＋ALIKED1024でIMG_2598が4照合・171採用点で成立した。ALIKEDのみ1024では多数の再試行を経て試験のメモリ安全上限に到達した。2593は速くなったが2590は遅くなったため、全条件での高速化やメモリ問題の解消を保証しない。
従来との姿勢差は約0.05〜0.10°、0.8〜2mm相当だが、独立真値からの位置誤差ではない。画像再投影誤差の同等性はCT表示一致精度の同等性を証明しない。小さい模様の損失、ROIや候補順の変化、近似HFOVの誤差が残る。
