# 登録実写の領域別姿勢採点：実装と比較

2026-10-04。実行中MacAR・カメラ・写真・地図の内容は変更していない。コードの反映にはPythonプロセスの再起動が必要。

## 実装

登録実写の候補評価を、生inlier数優先から共通対象cropの8×8領域評価へ変更した。領域ごとに最大1票とし、領域内再投影誤差の中央値 `e` とPnP閾値 `t` から `max(0,1-(e/t)^2)` を合計する。8×8・中央値は初期設定であり最適性は未立証。

- 最終選択・早期終了の順位・別姿勢の70%支持判定を同じ点数へ揃えた。
- 既存QCの通過を優先する。必要点数・比率・平均/P95誤差・3D分布・姿勢差の閾値は維持した。
- PnPは全対応点を使い、RANSAC/LMを変更していない。候補ごとに区画を作り直さず、密集点を独立票として数えない。
- `quality.spatial_score` に点数、占有領域数、領域平均誤差、crop、閾値を記録する。既存の表示inlier数は生の点数のまま。
- `reference_candidate` ログに採点と候補姿勢を保存する。
- 比較用の3DGS仮想画像経路・単独の追跡PnP・並行LK引き継ぎは変更していない。

仕様は [spatial-pose-scoring.md](docs/spatial-pose-scoring.md)。実装は `spatial_pose_scoring.py` と `registered_aliked_live.py`。

## 実写比較

`benchmark_spatial_pose_scoring.py --output output_spatial_scoring_20261004` で、写真1枚ごとに新しいMPSプロセスを使った。同一ALIKED特徴点・ROI・LightGlue・候補集合・PnP/QCから旧採点と新採点を比較した。途中打ち切りは無効化しTop3の全候補を照合。どちらかFAILなら同じ特徴点でTop10へ拡張する条件としたが、今回は両方とも全24枚でTop3 PASS。XYZ-only再試行は使っていない。

対象は前回比較の全24枚（検証写真フォルダのIMG_2589〜2600の12枚、RC姿勢のある12枚）。RC写真自身と±5フレームを照合参照から除外。地図はstage_48の72,547点、3DGS粗検索は現在既定の元参照128視点。ALIKED入力1600 px・上限2000点、F閾値3 px、PnP閾値4 px、平均誤差上限3 px。RC写真は保存内部パラメータ、新写真はHFOV 72°近似を使用。

| 評価 | 旧採点 | 新採点 |
| --- | ---: | ---: |
| 検証写真のQC PASS | 12/12 | 12/12 |
| 検証写真の面方向判定一致 | 12/12 | 12/12 |
| RC写真のQC PASS | 12/12 | 12/12 |
| RC姿勢との差が既定評価範囲内 | 11/12 | 11/12 |
| RC回転差中央値 | 0.196° | 0.156° |
| RCカメラ中心差中央値 | 2.316 map units | 1.867 map units |
| RC回転差最大 | 1.668° | 1.668° |
| RCカメラ中心差最大 | 17.955 map units | 17.955 map units |

評価範囲は回転差5°以下・中心差が対象robust対角長の5%以下。物理真値ではなくRCのSfM姿勢との比較。検証写真の面方向はカメラ中心の方位区間による粗い判定で、精密な姿勢真値ではない。

選択参照は検証写真7枚、RC写真3枚の計10/24枚で変わった。例えばIMG_2600は129 inliers/16領域/14.088点から113 inliers/17領域/15.611点へ変わった。IMG_2595では両方145 inliersだが、11領域/10.238点から16領域/14.273点へ変わった。全体の生inlier平均誤差が常に小さくなる設計ではなく、領域の支持と領域ごとの誤差を評価する。

**00542.pngの中心差超過は残る。** 旧・新とも00594.pngを選び、QCはPASSだがRC中心から17.955 map units離れる。今回の採点変更で精度が保証されたとは言えない。候補生成・PnP内部の仮説生成や、似た面の誤対応を解決する変更ではない。

採点関数の追加時間は151候補で中央値0.082 ms、P95 0.296 ms。再投影の再計算と既存QCはこの関数時間に含めていない。モデル初期化を含む全照合時間や、実運用の早期終了による速度改善を測った結果ではない。

結果・全候補は [summary.json](../data/MacAR/output_spatial_scoring_20261004/summary.json)、入力・写真パス・コード/地図SHAは [inputs.json](../data/MacAR/output_spatial_scoring_20261004/inputs.json)。集計の写真種別キーを修正したため、開始時のbenchmarkソースをsnapshotで保持し、修正後のSHAを `statistics_code_sha256` に記録した。採点本体・実写経路の測定時SHAは現行実装と一致する。

## 自動テストと残る確認

追加テストを先に失敗させ、密集点より広域候補を選ぶこと、低い生inlier数の広域競合を見逃して早期終了しないことを確認してから実装した。密集の水増し、領域平均誤差、誤差閾値での正規化、共通crop、QC優先、最終選択、競合FAIL、同じ領域証拠に生点数を足しても順位が変わらないことを検証する。

全465テストがPASS。実行結果は [tests.log](../data/MacAR/output_spatial_scoring_20261004/tests.log) に保存。実カメラ・CTの物理位置精度は未検証。再起動後の登録実写モードで、ゆっくり回り込んだ際に面の取り違え・姿勢の跳び・FAIL増加がないかを確認する必要がある。実写比較では候補集合を揃えるため早期終了を無効化しており、実運用で同じ候補が必ず選ばれることまでは保証しない。
