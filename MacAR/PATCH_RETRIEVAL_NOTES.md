# 3DGS coarse retrieval: パッチ配置＋方向分散（試験）

2026-09-28。対象はブラウザ版の通常3DGSライブモード。登録実写ALIKEDモードの検索方式は変更していません。

## 動作

`live → Auto ROI → DINO全体特徴Top-10 → maskedパッチ配置の再順位付け → 方向分散した3候補 → ALIKED/LightGlue → 既存XYZ → PnP/QC → LK追跡`

パッチと全体特徴は同じcropのDINO forwardから取得します。Auto ROIの検出推論は従来どおり別途必要です。参照パッチは事前キャッシュし、参照画像/モデル/設定が変われば再生成します。初回キャッシュ生成時間は探索時間とは別です。

16×16パッチについて、foreground mask内の同位置の特徴類似度と、相互最近傍パッチ対応の配置整合性を計算します。スコアは全体類似度25%、配置50%、対応整合性25%。image-space similarity RANSACは反転・大きなroll/scale・狭い支持領域を抑える補助スコアであり、物理的3D対応や姿勢を認定するものではありません。

再順位付け後、参照カメラ同士の回転差が原則35°以上となるよう局所照合候補を選びます。これはlive姿勢が既知という仮定ではなく、既知の参照カメラ姿勢による候補の分散です。同方向しか残らない場合はスコア順で補充します。10枚すべてにLightGlueを実行するわけではありません。既定の3枚だけです。

単純なパッチ順位の上位3枚では悪化しました。同一方向の別距離画像や類似面へ候補が集中するため、方向分散が重要でした。姿勢確定、AMBIGUOUS拒否、XYZ生成、カメラ取得、内部パラメータ、PnP/QCの閾値は変更していません。パッチスコアは確率・信頼度ではありません。

## 起動・比較

VS Codeで **MacAR: Browser Live (3DGS + MPR)** をF5で再起動し、ブラウザで通常3DGSモードを選びます。「3DGSの粗いview選択」の既定は新方式です。比較は停止後に「従来：全体特徴の類似度のみ」へ切り替え、同じ品質設定・候補数で開始します。

探索パネルにはglobal順位、配置スコア、配置整合性、パッチRANSAC支持数、実際の照合対象を表示します。パッチ支持数と最終PnP inlierは別です。Top-1は未確定候補です。

## 仮想画像72枚での比較

同じupper_negz_v2を入力と参照に使い、入力と同じazimuth/elevationを持つ参照2枚（距離違い）を除外しました。近傍はカメラ回転差30°以内。CPU、Auto ROI、同じ72入力で測定。JSONは`output_patch_retrieval_evaluation/evaluation.json`です。

| 指標 | 従来global | パッチ＋方向分散 |
|---|---:|---:|
| 実際の3照合候補内の近傍率 | 38/72（52.8%） | 64/72（88.9%） |
| Top-1平均角度誤差 | 93.1° | 123.0° |
| 残り候補を含むTop-10近傍率 | 95.8% | 95.8% |
| 粗検索中央値 | 118.2 ms | 211.8 ms |
| 粗検索95percentile | 123.1 ms | 241.6 ms |

補助比較ではglobalスコア＋方向分散だけでも55/72（76.4%）でした。パッチスコアだけの3候補は26/72（36.1%）。したがって改善をパッチだけの効果と解釈できません。Top-5には実際の照合3候補を先頭に置いた候補順を使用します。

この72入力を開発中にも使用したため、独立した汎化評価ではありません。Top-1は改善しておらず、離散viewの方向曖昧性も残ります。目的は候補内に正解近傍を残して後段に判断させることであり、連続6DoFの直接推定ではありません。

## 再実行

MacARディレクトリで：

```bash
TORCH_HOME="$PWD/.model_cache/torch" .venv/bin/python3 benchmark_view_retrieval.py \
  --views output_3dgs_reference_views_72_upper_negz_v2 \
  --modes dino-global dino-patch --device cpu \
  --output output_patch_retrieval_evaluation/evaluation.json
```

実写での方向改善・初期ローカライズ時間・ロスト率の確認はこれからです。近似XYZ、未校正K、CTとの登録精度は今回の変更では解消しません。
