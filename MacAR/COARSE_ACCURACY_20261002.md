# 現在の粗検索の精度：実写での評価

2026-10-02。現在のディスク上の128仮想view、DINOパッチ再順位付け＋方向分散、
Auto ROI、上位3候補をそのまま評価した。ALIKED・LightGlue・PnPは使わず、
検索結果の正解判定にも使っていない。アプリの設定・参照選択は変更していない。

結論：1位は多くの写真で近い方向を選ぶが、無条件の決め打ちには誤りが残る。
上位3候補まで残すと改善するが、その3候補にも正解方向がない例がある。

## 姿勢付き実写621枚

再構成元のRC/COLMAP画像621枚すべてを入力した。基準は保存済みの推定カメラ姿勢。
物体中心からカメラへ向かう単位ベクトル同士の角度を方向誤差とし、
30度以内を粗検索の正解とした。roll、カメラ距離、画像内の物体位置はこの指標に含まない。
カメラ回転全体の誤差は別途JSONに保存している。

| 条件 | 方向誤差30度以内 | 方向誤差60度超 | 方向誤差の中央値 |
|---|---:|---:|---:|
| 全体特徴だけの1位（並べ替え前） | 352/621（56.7%） | 139/621 | 23.3度 |
| 現在の最終1位 | 549/621（88.4%） | 32/621（5.2%） | 10.2度 |
| 現在の上位3候補の最良方向 | 587/621（94.5%） | 4/621 | 10.2度 |
| 現在の上位10候補の最良方向 | 609/621（98.1%） | 2/621 | 9.5度 |

全621枚について、仮想view集合には30度以内の候補が存在する。
したがって上位3から外れた34枚は、この30度基準では候補集合の方向不足ではなく
検索・並べ替え・候補選択で取りこぼしている。全候補から幾何的に最も近いviewの
方向誤差の中央値は8.4度であり、離散viewの間隔も誤差に含まれる。

方位330〜360度の110枚では、最終1位72/110（65.5%）、上位3候補86/110（78.2%）。
ほかの方位区間より低かった。方位30度ごとの件数を均等に重み付けした1位正解率は90.8%。
撮影方向の件数の偏りが全体の値に影響している。

例：00199.pngでは1位の方向誤差87.6度、2位は13.1度。
この入力を1位に固定すると、候補に正解近傍があるのに別方向を選ぶ。

![姿勢付き実写の誤検索例](../data/MacAR/output_coarse_accuracy_20261002/known_pose_failure.jpg)

**評価の範囲**：621枚は3DGS作成にも使った同じ撮影系列の画像で、近接フレームを含む。
独立した621回の試行でも、未知環境の成功率でもない。数値の基準も外部計測した真値ではなく
RC/COLMAPの推定姿勢。これは現在のモデルと撮影系列に対する検索精度の評価である。

## 別撮りの検証写真12枚

IMG_2589〜IMG_2600。4方向について近い撮影が3枚ずつある。
これらには数値の真値姿勢がないため、隣り合う側面のシール・テープ配置と左右関係を
目視で比較した。これは上の30度基準より広い「物理的な面配置の一致」で、
角度精度を認定する値ではない。

| 写真 | 最終1位の面配置 | 上位3内の一致 |
|---|---|---|
| IMG_2589〜2591 | 一致 | あり |
| IMG_2592〜2594 | 一致 | あり |
| IMG_2595〜2597 | 一致 | あり |
| IMG_2598 | 不一致 | なし |
| IMG_2599〜2600 | 一致 | あり |

面配置は1位11/12枚で一致した。角度の正解率91.7%とは解釈しない。
IMG_2595〜2597などでは面の見える幅が候補と異なり、面が一致しても連続姿勢は未確定。

IMG_2598は左側が上部4枚のシールの面、右側がテープ付きの多数のシールの面。
全体特徴の1位view_0055はこの面配置に一致するが、パッチ再順位付け後は
view_0062、0064、0053が上位3に選ばれ、同じ面配置が落ちる。
view_0056/0055は再順位付け後も5/6番目に残る。
この例では「候補画像がない」のではなく、並べ替えで正しい面配置の候補を落としている。
切り出しやパッチスコアのどの項が原因かは、この比較だけでは確定していない。

## GPUとの一致と時間

全件数値評価はCPUで実行した。実運用と同じMPSでも、別撮り12枚と姿勢付き48枚を比較。
48枚は元系列全体から等間隔の添字で選んだ。全60枚で検出ROI・1位・上位3の順位が一致した。
これは全621枚のMPS一致を保証するものではないが、確認した範囲では判定差はない。

独立プロセスでの粗検索時間は、CPU全621枚で中央値222.6ms、95%点265.6ms。
MPSの姿勢付き48枚では中央値185.3ms、95%点221.6ms。
モデル/参照初期化、写真デコード、ALIKED、参照照合、PnP、アプリ描画は含まない。
実アプリで発生する長い待ち時間を、この速度から否定することはできない。

## 判断

1位の方向を優先して良質な3D対応を探す案は引き続き有効だが、1位だけを固定するのは
今回確認した誤検索を回復できない。上位候補と物理的な3D対応で確認する余地が必要。
上位3にもない例には、候補拡張または未確定判定が必要になる。
全体特徴のみへ戻すと、この621枚では大幅に悪化するため、IMG_2598だけを根拠に戻せない。

既存の72合成入力の評価は旧72候補での開発時の結果。今回は128候補の実写評価であり、
両者を同じ条件の精度として比較しない。

## 再現用ファイル

- `evaluate_coarse_real_photos.py`: 評価スクリプト。通常アプリの処理を変更しない。
- `output_coarse_accuracy_20261002/queries.jsonl`: 全621＋別撮り12枚のROI、候補、角度、時間。
- `summary.json`: 集計、方位別集計、設定と入力パス。
- `metadata.json`: 128候補、manifest SHA256、スクリプトSHA256。
- `visual_audit.json`: 別撮り12枚の面配置の目視判定。
- `backend_agreement.json`: CPU/MPSの60枚比較。

```bash
TORCH_HOME="$PWD/.model_cache/torch" .venv/bin/python evaluate_coarse_real_photos.py \
  --output NEW_OUTPUT_DIRECTORY --photo-root VALIDATION_PHOTO_DIRECTORY --device cpu
```
