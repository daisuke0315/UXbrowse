# ViewSync Builder 設計と検証記録

## 現行要求（2026-10-22）

添付された[要件定義書 v1.0](requirements-v1.md)全体を段階的に実装・検証する。
研究用の既存データやMacARの作業中の変更には手を加えない。
ブラウザビューアとMacARの現在の方式は保持する。

## 構成

- `ViewSyncBuilder/`にPythonエンジン、FastAPI、静的UI、テスト、配布スクリプトを配置する。
- 作成する研究データは既定でGit対象外の`data/ViewSyncBuilder/Projects/`に保存する。
- エンジンはUIに依存させず、CLIから同じ処理を実行する。
- 処理は入力→ALIKED→LightGlue/幾何検証→SfM→手動GCP三角測量/Sim(3)→固定GCP BA→独立QC→出力とする。
- 外観生成を選んだ場合、QC後の固定カメラから歪み補正→CPU MVS→高密度点群→メッシュ→元写真テクスチャ→出力へ進む。
- 結果は実行IDごとに分離し、原本・過去の結果を上書きしない。設定・入力・モデルハッシュで再利用を判定する。
- プロジェクト切り替え時は、前のプレビュー・品質指標・座標表示・保存リンクを消し、新しいプロジェクトの結果を明示的に開く。
- 特徴抽出は画像単位でも保存する。対象画像の追加・除外でグループDBを作り直す場合、同一の正規化画像・マスク・ALIKEDモデル/設定の特徴は再推論せず、新しいCOLMAP DBへ登録する。カメラ内部パラメータと画像IDは新しいDB側で割り当てる。

## 座標契約

### CT欠損の内蔵補間（2026-10-23のユーザー要求）

元DICOMを保持し、読み込み時にシリーズ検証・内部欠損の検出・HU線形補間・MPR表示までアプリ内で実行する。外部のMHA変換を必要としない。
既存の「欠損は常にエラー」の仕様を変更する。混在UID/方向/画素間隔、重複位置、非整数間隔、不整合な面内移動は引き続きエラー。
基本間隔は一貫したSpacingBetweenSlicesがあればそれを使い、なければIPPから最小正間隔を求め、その間隔が過半数の隣接対に存在する場合だけ採用する。SliceThicknessを間隔の代用にしない。
元断面のHUはそのまま保持し、観測位置間の整数格子に限って線形補間する。端点の外挿や、観測できない先頭・末尾の欠損枚数の推定はしない。
補間の方式、基本間隔と根拠、元断面の位置・SOP UID・出力インデックス、生成断面のLPS位置・両端元断面・補間重みを保存する。原DICOMの複製とハッシュを保持し、補間断面を元DICOMに偽装しない。
CT入力画面に元枚数・生成枚数と補間位置、MPRに補間の影響を受ける画素数を表示する。
GCP/評価点のLPS位置から元断面・補間影響・CT範囲外をサーバー側で判定し、保存と実行スナップショットに記録する。補間断面の隣接領域でMPR線形サンプルが補間値を含む場合も影響ありとする。
補間影響のある拘束GCPや評価点を使う結果はCT精度「未検証」とし、点ごとのTREは残しつつ元断面由来と補間影響ありの集計を分ける。点の自動除外・観測値変更はしない。
実行・QC・最終出力へ補間情報を引き継ぐ。これは欠損を診断用に復元したり、測定精度を保証したりする機能ではない。

CTフォルダに複数シリーズがある場合、選択一覧はシリーズ番号・説明・スライス数を表示し、UIDで選択を確定する。同じ説明や同じスライス数のシリーズを区別できるようにする。写真との対応シリーズは自動推定しない。

- CTのDICOM患者座標（LPS、mm）を正準座標とする。
- DICOMのUVは列/行、PixelSpacingは行/列の順。IPPは画素中心。
- カメラ外部行列は`T_camera_from_CT_LPS`、カメラ座標はCOLMAPの右/下/前とする。
- Sim(3)は`X_CT = s R X_SfM + t`。姿勢の回転を`R_cam R^T`、並進を`s t_cam - R_cam R^T t`に変換する。
- 出力の軸・単位を変更する場合は変換行列を保存する。

## 拘束BAの検証方針

PyCOLMAPのCeres BAで、手動GCP観測を自動特徴とは別の2D観測として追加し、CT XYZを持つ3D点を固定する方式を最初に検証する。
固定GCPでゲージを拘束するため、SfMの任意の第一カメラ固定を持ち込まない。
独立評価点はSim(3)、BA、GCP品質判定に混入させない。
4点以上を推奨し、最低3点の非共線拘束GCP、各点2画像以上の観測と十分な視差が必要。
不正な座標・反転・観測重複・不整合DICOM・収束失敗を正常終了にしない。

## 品質判定

再投影誤差（px）、独立評価点TRE（mm）、表示重畳誤差を区別する。
評価点なしは「未検証」。BA未収束は「不合格」。単一データのTREだけで複数条件10件の性能目標達成を主張しない。
暫定2/3 mm目標は要件定義の研究目標であり、臨床基準ではない。
GCP観測の再投影上限は初期のソフトウェアQCとして既定4 px（設定可能）とし、上限超過・非有限投影・非収束があれば最終成果物を正常出力しない。これはCTの物理精度判定とは別であり、CT側の測定誤差を保証する閾値ではない。
BAがこのQCに不合格の場合も途中モデルと`qc.json`を保存し、結果画面で明示的に「不合格」と表示する。独立評価のTREはこの場合計算せず、正常出力のZIPは生成しない。

## 配布用プレビューの境界

### メッシュ・テクスチャ生成（2026-10-23追加要求）

公式OpenMVS 2.4.0 macOS arm64版を同梱する。取得は開発時のみとし、アプリ起動時のネットワークやHomebrewを必要としない。
CTモードでは、同じ実行の固定CT-GCP BAとBA品質判定を通過したモデルだけを外観生成へ渡す。COLMAPで歪みを補正し、OpenMVSへPINHOLEモデルを渡す。MVS中にカメラ姿勢を再推定しない。座標正規化と仮想タワー点の追加を無効にして、CT LPS/mmを保つ。
写真だけの形状確認用にSfM試作モードを用意する。これは任意座標・任意単位で、CT整合やCT精度を意味しない。試作のDenseを後のCT結果へ流用せず、CT拘束後の実行で新たに生成する。
Sparseだけの出力も選択できる。外観生成はDense・Mesh・Textureで工程とログを分け、中断・失敗を記録する。失敗時には既存Sparseと研究用の途中結果を保持し、完成したメッシュとして配布しない。
Dense PLY、メッシュPLY、テクスチャ付きOBJ/MTL/画像と自己完結GLB、生成条件・元カメラのハッシュ・座標契約を出力する。CTモードのPLY/OBJはLPS/mm。GLBはルートノードで`(X,Y,Z)_glTF = 0.001×(-X,Z,Y)_LPS`へ変換し、Y-up/mにする。正逆変換行列を保存し、アプリ内プレビューでは逆変換してCT/Sparseとそろえる。写真試作GLBは任意座標のまま、物理単位未確定と明記する。ブラウザではSparse/Dense/Mesh/Textureの表示を切り替える。
OpenMVSの形状を変える平滑化・穴埋めは初期設定で無効。未撮影面のテクスチャは推測して埋めず、未観測として扱う。背景を除く必要がある場合は撮影・ROI条件を確認する。
既存20画像の目視試験で継ぎ目の色補正が極端な色を生成したため、初期設定ではglobal/local seam levelingを無効にし、元写真から採取した色を保持する。継ぎ目の見え方は撮影条件に依存する。
OpenMVSはAGPL-3.0。ライセンス・対応ソースと取得元を同梱し、商用配布条件を確認済みとはしない。公式情報：[配布](https://github.com/cdcseacave/openMVS/releases/tag/v2.4.0)、[使用法](https://github.com/cdcseacave/openMVS/blob/v2.4.0/docs/wiki/Usage.md)、[ライセンス](https://github.com/cdcseacave/openMVS/blob/v2.4.0/COPYRIGHT.md)。

ローカル検証用のmacOS arm64パッケージをPyInstallerで作成する。Python、PyCOLMAP、同梱のONNX対応COLMAP、固定ハッシュのALIKED/LightGlueモデルと静的UIを収める。実行時にはモデル取得やpip installを行わない。
開発者によるパッケージの生成は、開発環境がない別PCでの受入試験・署名/公証・再配布ライセンス監査の完了とは区別する。Windowsは未検証。

## 検証手順

テストを先に追加し、意図した失敗→最小実装→成功の順を記録する。
数値検証には既知の合成カメラ/3D点と独立評価点を使用し、実写精度の検証とは区別する。
ブラウザUIはローカルサーバーで操作確認する。未実施の実機・実写確認は未確認として残す。
