# ViewSync Builder 要件定義書

**CT-GCP拘束型フォトグラメトリ生成ソフトウェア**

- バージョン：1.0
- 作成日：2026年10月22日
- 開発段階：初期要件定義
- 提供形態：スタンドアロン型ローカルWebアプリケーション

---

## 1. 開発目的

### 1.1 概要

複数の可視光画像から三次元モデルを再構成し、CT画像由来の既知三次元座標をGround Control Point（GCP）としてBundle Adjustment（BA）に組み込むことで、CT患者物理座標系に整合した外観三次元モデルを生成するソフトウェアを開発する。

通常のフォトグラメトリでは、画像間の特徴点対応から相対的な三次元構造とカメラ姿勢を推定する。

本ソフトウェアでは、CTから得た既知の物理座標を再構成の拘束条件に組み込み、モデル生成段階からCT患者座標系との整合性を確保する。

### 1.2 達成目標

1. RealityCapture等の商用フォトグラメトリソフトウェアに依存せず、三次元モデルを生成できる。
2. ALIKED＋LightGlueによる特徴点対応を用いてSfMを実行する。
3. CT由来GCPを利用した拘束BAで、カメラ位置姿勢と三次元特徴点を最適化する。
4. 同一座標系でSparse点群、高密度点群、メッシュ、テクスチャ付き外観モデルを生成する。
5. 三次元モデル、カメラ姿勢、ALIKED特徴点地図、精度評価結果を保存できる。
6. ZIPファイルを展開するだけで、ブラウザを操作画面として使用できる。

### 1.3 対象範囲

本ソフトウェアの主目的は、オフラインでの外観三次元モデル生成である。

ライブカメラによる姿勢推定、CT-AR重畳、DINOv2粗検索、LK追跡は対象外とする。ただし、将来的にこれらと接続できるデータ出力構造を設ける。

3DGSの生成についても初期開発の必須機能とはせず、既知カメラ姿勢と画像データの出力によって後から接続可能とする。

## 2. システム構成

### 2.1 アーキテクチャ

以下の3層構造を採用する。

**フロントエンド**

- HTML / CSS / JavaScript（TypeScriptを推奨）
- Three.jsによる三次元表示
- 写真、CT、GCPの入力・確認
- 再構成条件の設定
- 処理進捗の表示
- 結果の確認・保存

**バックエンド**

- Python
- FastAPI
- pydicom / SimpleITK
- NumPy / SciPy
- プロジェクト管理
- DICOM座標処理
- GCP管理
- 再構成ジョブの制御
- QCおよびファイル出力

**再構成エンジン**

- COLMAP
- PyCOLMAP
- ONNX Runtime
- ALIKED
- LightGlue
- SfM
- Ceres SolverによるBA
- MVS / Mesh / Texture生成

各層を分離し、再構成エンジンはブラウザUIなしでも実行可能な構成とする。

### 2.2 動作方式

1. ZIPファイルを展開する。
2. 同梱ランチャーを実行する。
3. Pythonバックエンドと再構成エンジンが起動する。
4. ローカルHTTPサーバーを起動する。
5. 既定のWebブラウザに操作画面を表示する。
6. ユーザーが写真・CTを入力してモデル生成を実行する。

ユーザーにPython、Node.js、COLMAP等の個別インストールを要求しない。

必要な実行ファイル、ライブラリ、学習済みモデルをアプリケーションに同梱する。

## 3. 処理ワークフロー

### 3.1 基本処理

```text
① 写真・CTの読込み
         ↓
② ALIKED特徴点抽出
         ↓
③ LightGlueによる特徴点対応
         ↓
④ 幾何検証・誤対応除去
         ↓
⑤ SfMによる初期再構成
         ↓
⑥ CT-GCPの登録
         ↓
⑦ CT座標系への初期整合
         ↓
⑧ GCP拘束BA
         ↓
⑨ 品質管理・精度検証
         ↓
⑩ MVSによる高密度再構成
         ↓
⑪ メッシュ・テクスチャ生成
         ↓
⑫ データ出力・保存
```

Sparse再構成完了時点でも、結果を保存して終了できるものとする。

## 4. 機能要件

### FR-01：プロジェクト管理

- 新規プロジェクトを作成できる。
- 保存先フォルダを指定できる。
- 既存プロジェクトを再開できる。
- 入力画像、CT、GCP、計算結果、設定を保持する。
- 処理途中から再実行できる。
- 元画像や原データを上書きしない。
- プロジェクトと計算結果を別々に管理する。

### FR-02：画像入力

- JPEG、PNG形式の画像を取り込める。
- 複数画像を一括選択できる。
- EXIF情報および画像回転を適切に処理する。
- 各画像に一意のIDを割り当てる。
- 不要な画像を処理対象から除外できる。
- 画像の解像度、枚数、カメラ情報を表示する。
- 必要に応じて対象領域ROIやマスクを設定できる。

初期開発では、iPhone等の一般的なRGBカメラから取得した写真を主対象とする。

画像マスクは原本に適用して上書きせず、別データとして保存する。

### FR-03：CT入力・座標取得

- DICOM CTシリーズを読み込める。
- 読み込んだCTをMPR表示できる。
- 以下のDICOM情報を取得する。

  - ImagePositionPatient（IPP）
  - ImageOrientationPatient（IOP）
  - PixelSpacing
  - SeriesInstanceUID
  - FrameOfReferenceUID
  - スライスごとの位置情報

- CT画像上で指定した点の患者物理座標を算出する。
- DICOM座標系（原則LPS、単位mm）を基準座標系とする。
- 不整合なシリーズ、スライス欠損、座標情報の異常を検出する。

2026-10-23追加要求：欠損検出から補間、MPR、補間由来の記録まで一つのシステム内で完結する。元DICOMを保持し、基本間隔を特定できる内部の整数格子欠損をHU線形補間する。非整数間隔・重複・不整合は拒否する。補間影響のあるGCP/評価点は識別し、元断面に基づく評価と区別する。具体的な採用条件・記録項目は`implementation.md`を現行設計とする。

### FR-04：GCP設定

- CT画像上でGCPを登録できる。
- GCPごとに一意のIDを付与できる。
- 各GCPのCT物理座標XYZを保存する。
- 複数の写真上で同一GCPの2D座標UVを指定できる。
- GCPと写真上の観測点の対応を確認・修正できる。
- 誤指定したGCPを除外できる。
- 拘束GCPとは別に、精度評価専用の独立評価点を設定できる。

初期運用では4点以上の拘束GCPを推奨する。

GCP数だけでなく、三次元的な分布、観測画像数、幾何学的な退化条件を確認する。一直線上への集中や極端に狭い領域への偏在は警告対象とする。

GCPの自動検出は初期必須としない。手動指定を基本とする。

### FR-05：ALIKED特徴点抽出

COLMAPのALIKED機能を使用する。

- 各写真の特徴点を抽出する。
- 特徴点の画像上の2D座標を取得する。
- 特徴記述子を取得する。
- 特徴点のスコアを取得する。
- 特徴点と画像IDを対応付けて保存する。
- 同一画像について同じ設定の特徴抽出を重複実行しない。

初期候補はALIKED N16ROTとし、N32等との比較を可能とする。

### FR-06：LightGlueによる特徴点照合

- ALIKED特徴記述子から画像間の対応点を推定する。
- 画像ペアごとに照合を実行する。
- 対応する特徴点IDを保存する。
- 対応信頼度や照合結果を記録する。
- 画像間の重複領域が少ない場合の失敗を検出する。
- 撮影順や画像の近傍関係を利用して、照合対象ペアを制御する。

全画像ペアの総当たり照合を必須とせず、データ規模に応じたペア選択方式を採用する。

### FR-07：幾何検証

LightGlueで得た対応点について、幾何学的一貫性を検証する。

- Fundamental MatrixまたはEssential Matrixを利用する。
- RANSAC等によって誤対応を除去する。
- Inlier / Outlierを記録する。
- 幾何検証に失敗した画像ペアを除外する。
- 検証結果から複数画像にまたがる特徴点トラックを生成する。

この段階では未知の画像間相対姿勢を推定するため、参照画像の姿勢が既知であることを前提としない。

### FR-08：SfMによる初期再構成

COLMAPのSfM機能を利用する。

- 画像間の対応点から初期カメラ姿勢を求める。
- 各画像のカメラ外部パラメータを推定する。
- 三角測量によって特徴点のXYZを推定する。
- 必要なカメラ内部パラメータを推定または設定する。
- 通常のBAで初期再構成を最適化する。
- Sparse点群を生成する。

出力するものは以下とする。

- カメラ内部パラメータ
- カメラ位置・姿勢
- Sparse点群
- 特徴点観測トラック
- 再投影誤差
- 登録成功画像一覧
- 再構成失敗画像一覧

初期SfMの座標系は任意であり、まだCT患者座標系とは一致していない。

### FR-09：CT座標系への初期整合

SfMのGCP対応点とCTのGCP座標を利用して、初期座標系整合を行う。

- SfM側の対応するGCPの三次元位置を取得する。
- CT側のGCP座標と対応付ける。
- Similarity Transformation（Sim(3)）によって初期変換を求める。
- 初期変換をカメラ姿勢およびSparse点群に適用する。
- 初期整合残差を記録する。

初期整合は後段の拘束BAの初期値を作るものであり、最終結果をこの変換のみで決定しない。

GCPがSfMの自動特徴点と一致しない場合も、写真上の手動2D観測と再構成済みカメラを利用してGCP位置を推定できる方式を設ける。

### FR-10：CT-GCP拘束BA

**本ソフトウェアの中核要件とする。**

GCPのCT物理座標を基準として、画像再投影誤差を最小化する。

基本式：

\[
\min_{\mathbf R,\mathbf t,\mathbf X}
\sum_{(i,j)\in\mathcal O}
\rho\left(
\left\|\mathbf u_{ij}-
\pi(\mathbf K_i,\mathbf R_i\mathbf X_j+\mathbf t_i)
\right\|^2
\right)
\]

さらに、CT由来の既知GCP座標 \(\mathbf G_k^{CT}\) に対する画像上の観測誤差を同時に扱う。

\[
+\sum_{(i,k)\in\mathcal G}
\rho_G\left(
\left\|\mathbf u_{ik}^{GCP}-
\pi(\mathbf K_i,\mathbf R_i\mathbf G_k^{CT}+\mathbf t_i)
\right\|^2
\right)
\]

最適化する変数：

- 各画像のカメラ位置
- 各画像のカメラ姿勢
- GCP以外の一般特徴点の三次元座標
- カメラ内部パラメータ（許可した場合）

固定する変数：

- CTから定義したGCPの三次元座標（初期方式）

必要な実装：

- CT-GCPの固定座標を最適化問題に組み込む。
- GCP画像観測の残差を計算する。
- カメラ位置・姿勢および一般3D点を最適化する。
- カメラ内部パラメータを固定／最適化できる設定を設ける。
- 不正なGCP、外れ値、収束失敗を検出する。
- BA前後の誤差とカメラ姿勢の変化量を保存する。

PyCOLMAPの固定点設定とCeresの独自残差追加を実装候補とする。

ただし、既存SfMモデルへのGCP観測の登録方法、ゲージ固定との整合、最適化対象の選択は、先行する技術検証で確定する。

将来的にはGCP測定の不確かさを考慮した重み付き拘束も実装可能な構造とする。

### FR-11：Sparseモデル出力

CT-GCP拘束BAで得られた結果を保存する。

- CT患者座標系のSparse点群
- 各カメラの外部パラメータ
- 各カメラの内部パラメータ
- 特徴点XYZ
- 特徴点観測トラック
- GCP情報
- 座標変換情報
- 最適化結果
- 再投影誤差

COLMAP互換形式とPLY形式を基本出力とする。

### FR-12：ALIKED特徴地図生成

既存のViewSync/MacARで使用できる参照特徴地図を生成する。

保存項目：

| 項目 | 内容 |
|---|---|
| Image ID | 撮影画像ID |
| Keypoint ID | 画像内特徴点ID |
| UV | ALIKEDの2D特徴点座標 |
| Descriptor | ALIKED特徴記述子 |
| Point3D ID | 対応する三次元特徴点ID |
| XYZ | CT患者座標系での三次元座標 |
| Track | 同じ特徴を観測した画像 |
| Score | 特徴点検出スコア |
| Reprojection Error | 再投影誤差 |
| Validity | 三次元座標が有効かどうか |

特徴点のXYZは、CT-GCP拘束BA後の最終座標を使用する。

三角測量に成功していない特徴点には、推定していないXYZを付与しない。

画素単位の密なXYZマップは必須とせず、Sparse特徴地図を標準とする。

### FR-13：MVSによる高密度再構成

最適化されたカメラ姿勢を使用してMVSを実行する。

- カメラ姿勢を確定する。
- 必要に応じて画像の歪みを補正する。
- 各画像の深度情報を推定する。
- 深度情報を統合する。
- 高密度点群を生成する。

**CT-GCP拘束BAより前のカメラ姿勢を使ったDense結果を、そのまま最終出力として流用しない。**

対応するGPU環境がない場合はSparse出力まで実行でき、Dense生成機能のみ利用不可または代替エンジンへ切り替えられる構造とする。

### FR-14：メッシュ・テクスチャ生成

- 高密度点群からメッシュを生成する。
- 元画像からテクスチャを生成する。
- 必要に応じてポリゴンを簡略化する。
- UVおよびテクスチャ情報を保持する。
- 最終モデルをプレビューできる。

出力形式：

- OBJ
- PLY
- GLB（変換処理を含む）

GLB等の表示用形式で座標軸や単位を変換した場合は、その変換情報を必ず保存する。

### FR-15：品質管理（QC）

計算結果について、以下を評価する。

- 画像登録成功率
- 特徴点トラック数
- Inlier数
- 再投影誤差
- GCP拘束残差
- カメラ姿勢の変化
- 独立評価点の位置誤差
- モデル生成成功・失敗
- エラーの空間的分布

独立評価点について、CT座標と独立に再構成されたXYZを比較できる場合、3D位置誤差をTREとして求める。

\[
TRE_k=\left\|\mathbf X_k^{model}-\mathbf X_k^{CT}\right\|
\]

また、CT評価点を写真上へ投影した位置と実際の観測位置との差を画素単位で求める。

**3D座標誤差、画像上の再投影誤差、表示重畳誤差は区別して管理する。**

QCでは、平均・標準偏差・中央値・最大値・失敗件数を表示する。

独立評価点が存在しない場合、再投影誤差だけでCTに対する位置精度が保証されたと判定しない。

### FR-16：結果プレビュー

Three.jsを利用して以下を表示する。

- Sparse点群
- Dense点群
- テクスチャ付きメッシュ
- カメラ配置
- GCP
- 独立評価点
- 座標軸

モデルの回転、拡大、移動、点群・メッシュの切り替えを可能とする。

### FR-17：進捗・ログ管理

- 各工程の進捗を表示する。
- 処理済み画像枚数を表示する。
- 特徴点数・マッチング件数を表示する。
- 処理時間を記録する。
- 処理失敗時に原因を表示する。
- 計算をキャンセルできる。
- 安全な中断地点から再開できる。

処理途中の有効なデータは保持し、再実行時に利用可能とする。

## 5. 座標系の要件

### 5.1 基準座標系

全体の基準座標系をDICOM患者座標系（原則LPS）とする。

- X：患者左方向
- Y：患者後方
- Z：患者頭側
- 単位：mm

### 5.2 カメラ座標

カメラ姿勢は変換方向を明示する。

正準形式を

`T_camera_from_CT_LPS`

とする。

COLMAP等の外部形式から読み込む場合は、カメラ中心とworld-to-camera変換の違いに注意する。

### 5.3 変換の保持

以下を保存する。

- SfM初期座標系
- CT患者座標系
- 初期Sim(3)変換
- BA最適化後のカメラ外部パラメータ
- 出力形式ごとの座標変換
- 単位

座標の左右反転、軸順序、スケール誤りが発生していないことをテストする。

## 6. UI要件

標準画面は5つとする。

### 画面1：プロジェクト管理

新規作成、既存プロジェクト選択、保存先指定、直近ジョブ確認。

### 画面2：画像・CT読込み

写真一覧、撮影画像のプレビュー、CTシリーズ選択、MPR表示、ROI指定。

### 画面3：GCP設定

CT上の三次元座標、写真上の二次元対応点、GCP ID、観測数、拘束用／評価用の区別を管理する。

### 画面4：モデル生成

ALIKED、LightGlue、SfM、GCP整合、拘束BA、QC、MVS、メッシュ生成を順に実行する。

「全自動実行」と「工程別実行」の両方に対応する。

### 画面5：結果確認

三次元モデル表示、カメラ・GCP表示、QC結果、出力、処理ログを確認する。

## 7. データ保存仕様

プロジェクトフォルダは以下を基本とする。

```text
ViewSyncBuilder/
  launcher/
  backend/
  frontend/
  models/
  engines/

Projects/
  Project001/
    manifest.json

    input/
      images/
      ct/

    control/
      gcp.json
      evaluation_points.json

    cache/
      aliked/
      lightglue/

    reconstruction/
      sparse_initial/
      ct_aligned/
      ct_ba/
      dense/
      mesh/

    output/
      sparse/
      mesh/
      feature_map/
      cameras/
      qc/

    logs/
```

原本、途中生成物、最終成果物は分離する。

`manifest.json`にはソフトウェア版、依存ライブラリ版、モデルハッシュ、設定値、処理ID、入力ハッシュを保存する。

GCPや評価点の観測値は、再実行可能な形で保持する。

## 8. 非機能要件

### 8.1 配布

- ZIP展開方式
- OS別の実行ファイルを提供
- Python等の事前インストール不要
- 自動ブラウザ起動
- 完全ローカル動作
- 外部サーバー接続不要

初期開発はmacOSを優先し、商用配布を見据えてWindowsへの移植性を維持する。

### 8.2 パフォーマンス

主な対象は数十枚から数百枚程度の画像群とする。

初期検証は20〜100枚、拡張検証は約500枚を想定する。

処理速度については、CPU、GPU、画像解像度、画像枚数ごとに実測する。

現段階では特定の処理時間を保証しない。

### 8.3 再現性

- 同じ画像群
- 同じGCP
- 同じ設定
- 同じアルゴリズム版
- 同じ学習済みモデル

を指定した場合、結果を比較できるよう、実行条件とログを保存する。

非決定的処理によるばらつきがある場合、その条件も記録する。

### 8.4 安全性

- ローカルHTTPは原則127.0.0.1に限定する。
- 患者データを外部へ自動送信しない。
- プロジェクト操作による原本破壊を防ぐ。
- 処理失敗時は不正なモデルを正常終了として扱わない。
- 個人識別情報を不要にログへ出力しない。
- ソフトウェアと学習済みモデルの再配布ライセンスを確認する。

### 8.5 品質未達時の扱い

独立評価点が不足する場合やBAが正常収束しない場合は、CT座標整合精度を「未検証」または「不合格」と表示する。

生成したモデルは研究用に保存できても、所定の精度を満たしたものと表示しない。

## 10. 受入試験

| ID | 検証項目 | 受入条件 |
|---|---|---|
| AT-01 | ALIKED特徴抽出 | UV・記述子・特徴IDが保存される |
| AT-02 | LightGlue照合 | 画像間の対応関係と幾何検証結果が保存される |
| AT-03 | SfM | RCを利用せずカメラ姿勢・Sparse点群を生成する |
| AT-04 | CT座標変換 | 既知の物理点に対して座標・軸・単位が一致する |
| AT-05 | GCP拘束 | CT側の固定GCPが最適化によって移動しない |
| AT-06 | BA | カメラ姿勢・一般特徴点が最適化され、収束結果が記録される |
| AT-07 | 独立評価 | 評価点がBAに混入せず、精度指標が算出される |
| AT-08 | 特徴地図 | ALIKEDの2D特徴と最終CT-XYZを対応付けられる |
| AT-09 | 外観生成 | 拘束BA後の姿勢からDense・Mesh・Textureを生成する |
| AT-10 | 配布 | ZIP展開後、追加の開発環境なしで動作する |

### 10.1 精度評価目標

既存RealityCapture方式では、特定条件の表示上一致性として0.45±0.26 mmが得られている。

新しい生成エンジンでは、まず同じ入力画像・GCP・独立評価点を使用し、次の項目を比較する。

- 生成成功率
- 独立評価点の位置誤差
- 最大誤差
- 誤差のばらつき
- GCP拘束による改善量
- 処理時間
- カメラ姿勢の安定性

最終的な開発目標として、複数条件・10件以上の検証で独立評価点の平均位置誤差2.0 mm以下、最大3.0 mm以下を暫定的に設定する。

ただし、既存方式の表示上一致性と、Sparse点群の3D位置誤差は評価方法が異なるため、同一指標として比較しない。

この目標値は達成済み性能ではない。

## 11. 技術的な未確定事項

実装前または初期開発中に以下を検証する。

1. **CT-GCP拘束の実装方法**  
   PyCOLMAPで固定3D点を登録する方式と、Ceresに独自残差を追加する方式のどちらを採用するか。

   既存RC方式と同程度の撮影条件で、十分なカメラ登録成功率と三次元点分布が得られるか。

   既知キャリブレーションを固定する方式と、焦点距離・レンズ歪みを同時最適化する方式の精度差。

4. **MVSの対応環境**  
   macOSや非CUDA環境での高密度再構成の実装方法。

5. **商用再配布**  
   COLMAP、ONNX Runtime、学習済みモデル、依存ライブラリ、生成エンジンのライセンス条件。

6. **医療用途への適合**  
   患者説明、診断支援、治療支援など、実際の使用目的に応じた薬事該当性と品質管理要件。

## 12. 開発上の優先原則

- 初めからすべてのフォトグラメトリアルゴリズムを自作しない。
- 利用可能なCOLMAPのSfM機能を優先して採用する。
- CT-GCP拘束BAを本ソフトウェア固有の中核処理とする。
- 座標整合性が確認できるまでDense・Mesh・3DGSの完成を優先しない。
- CT座標系・単位・カメラ姿勢の変換を明示的に管理する。
- 再投影誤差だけでCTとの位置整合精度を主張しない。
- 開発中の各処理は単独で試験可能とする。
- フロントエンドと再構成エンジンを分離し、将来的なSDK化を妨げない。

**初期開発の完了条件：RealityCaptureに依存せず、ALIKED＋LightGlue→SfM→CT-GCP拘束BAを実行し、CT物理座標系を持つSparseモデルと参照特徴地図を出力できること。**

この条件を満たした後、高密度外観モデル生成機能とスタンドアロン配布機能を追加する。
