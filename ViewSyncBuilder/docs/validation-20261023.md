## 現在の到達点

Phase 0の中核である「固定CT-GCPとカメラ/一般3D点の同時最適化」は、PyCOLMAP 4.2.1のCeres BAと合成データで成立を確認した。

## 0.3.0：CPU Dense・メッシュ・実写テクスチャ

公式OpenMVS 2.4.0 macOS arm64の4エンジンを固定ハッシュで導入した。歪み補正→高密度点群→メッシュ→OBJ/MTL/JPEGと画像埋め込みGLBを同じアプリのジョブで生成する。CTモードは同じ実行の拘束BA通過後のカメラを使い、カメラ姿勢・CT座標をMVSで再推定しない。写真だけの任意座標による形状試作も選べる。

既存20 PNGと仮想GCPの実行`89af41ff8ca7432a967d972919f91395`で20/20画像・Sparse 969点、Dense 54,150点、43,317頂点・86,470面とテクスチャ付きGLBを生成した。これは実測CT拘束の精度検証ではなく、狭い撮影範囲からの部分形状である。
目視でOpenMVSの継ぎ目色補正による極端な色を検出したため、同じメッシュを色補正なしで再テクスチャし、元写真の灰色・ベージュが保持されることを確認した。現行実装はglobal/local seam levelingを無効にし、平滑化・穴埋めも無効とする。

指定JPEG 9枚では、SIMPLE_RADIAL共有・PINHOLE共有・N32の複数条件でSparseまでは生成できたが、Denseの融合点が0となった。native側が終了コード0でも、有効な点群がなければアプリ側は失敗とし、完成メッシュや正常成果物ZIPを生成しない。現データで9枚から使えるメッシュが得られたとは扱わない。

OpenMVSの対応ソースZIP・LICENSE・COPYRIGHTを配布物に含める。AGPLと第三者の研究用途制限を含むため、商用再配布の監査済みとはしない。

既存549 PNGから全範囲にわたって40枚を等間隔に選び、新規の写真試作プロジェクトで実行した。既知のRC姿勢・地図は使用していない。画像ごとの寸法が異なるため、共有カメラの試行は入力検査で拒否した。その後、画像別PINHOLE・N16ROT・特徴上限2048・1600px・全780ペア・CPU 2 threads・MVS長辺1400px/解像度レベル1・テクスチャ4096pxで実行した。
