# 設計判断記録

### 2026-10-23：CT-GCP拘束生成をViewSync Builderへ分離

未知姿勢からのALIKED/LightGlue SfMと固定CT-GCPによるCeres BAを、独立したローカルWebアプリとして追加する。既知RC姿勢を使うMacARの前処理とは入力条件が異なるため、既存方式の置換にはしない。正準座標はDICOM LPS/mm、外部行列は`T_camera_from_CT_LPS`とする。[要求・設計・確認状況](../ViewSyncBuilder/docs/implementation.md)。

追加要求により、CT入力の内部欠損検出・HU線形補間・由来保存をBuilderに内蔵する。外部MHA変換を不要にし、原DICOMを保持する。基本間隔を特定できる整数格子欠損だけを補間し、重複・非整数間隔・座標不整合は拒否する。補間影響のあるGCP/評価点は識別し、精度保証へ混入させない。

0.3.0ではCPU対応の公式OpenMVS 2.4.0を同梱し、固定GCP BA後のカメラを歪み補正してDense→メッシュ→写真テクスチャへ渡す。点群0点やテクスチャ欠落を正常出力しない。写真だけの形状試作は任意座標と明示し、後のCT出力へDenseを流用しない。GLBのテクスチャを埋め込み、CT LPS/mmからY-up/mへの正逆行列を保存する。研究用プレビューとして対応ソースとAGPL/第三者ライセンスを同梱し、商用配布条件は未確認とする。

### 2026-10-23：補充の候補姿勢差による拒否・リセットを撤去

ユーザーの明示要求により、共通集合の新点/統合PnP間の距離による拒否（最終確認を含む）と追跡全リセットを削除する。登録実写高速descriptor補充の検索元姿勢差も候補拒否に使わず、contextと共に差の診断値だけを保存する。共通の現在UV–XYZで通常QC・空間支持・誤差を評価し、最良を採用する。最終確認失敗時は補充だけrollbackし、既存追跡は通常QC失敗まで継続する。初期/参照間競合や3DGSソース固有QC、投影候補選択は変更しない。[現行仕様・制約](../MacAR/docs/regional-replenishment.md)。

### 2026-10-22履歴：新旧共通集合でライブ姿勢を選ぶ

旧姿勢に合う新点だけを統合する循環を解消し、現在フレームの新旧UV–XYZから旧・新点・統合PnPを共通集合で評価する。空間均等票・誤差と通常QCを用い、対応数だけでは選ばない。旧姿勢との差は更新の拒否条件にせず、現在の対応から解いた新点PnPと統合PnPの競合、最終現在確認・rollbackを保持する。新点2倍・実写2枚合意による別枠置換と保守的補正は現行経路から撤去する。過去の測定は履歴として保存。[仕様](../MacAR/docs/regional-replenishment.md)。

### 2026-10-22履歴：新しい多数・広範囲の対応による追跡再初期化

旧追跡との位置差だけで良質な新対応を捨て続けない。登録実写2枚の独立PnP合意と通常QC、現在画像へのLK転送と独立PnP、旧点数の2倍以上・広範囲の新点を確認してから、旧点を混ぜず新しい姿勢/seedへ置換する。最終現在フレーム確認失敗はrollback。単一fresh点集合の固定100単位以内での上書き分岐は廃止し、合意付き置換へ一本化する。3DGS方式・通常補充・写真/固定検証は保持。[仕様](../MacAR/docs/regional-replenishment.md)。

### 2026-10-22：MacARコードとローカルデータの分離

コード・テスト・UIは`MacAR/`に保持し、元画像・生成物・モデルキャッシュは`data/MacAR/`へ集約する。実行時のデータルートを一元化し、VS Code設定・既定の入力/出力を新配置へ統一する。旧配置フォールバックは設けない。データは削除せず移動し、運用JSONのパス更新前の原本を保存する。過去ログ・測定結果は変更しない。Git履歴の書き換えとpushは別作業。[仕様](../MacAR/docs/data-layout.md)。

### 2026-10-22履歴：登録実写の別領域補充

高速なpose-local descriptor検索だけでは回収しにくい領域を、既知姿勢で選んだ最大2実写のLightGlue照合で補う。新視点イベント・初回・前回context開始から4秒以上の許可済み補充で使用し、全体DINO検索は繰り返さない。背景モードの4°方向変化・新区画では通常の待機を短縮し、100ms以内の画像から先行補充する。前景負荷・同時1件・独立PnP/QCと新旧支持による保守的補正を維持し、追加枠は既存点の少ない領域を優先。同じフレームで統合後のPnP/debugを更新する。[仕様と確認範囲](../MacAR/docs/regional-replenishment.md)。

### 2026-10-22：MacARライブの継続補充・MPS・カメラ再接続

同一視点で停止していた近傍補充を、同時1件・負荷予算・待機付きで継続する。厳格な最終PnP/QCは維持し、補充の副次ゲートだけRANSACと不整合な半閾値を解消する。ライブMPSのLightGlueは既存の明示attention経路を使用して未使用メモリをジョブ境界で回収する。cache解放単独、ALIKED canvas化、ALIKED CPU化は実測で増加を止められず不採用。停止時のカメラ解放をGPU待ちより先に行い、再接続の空フレーム・open失敗は有限回だけ再試行する。[仕様と制約](../MacAR/docs/live-refresh-recovery.md)。

### 2026-10-21：MacARブラウザ側性能のセッション記録

ブラウザのフレームID付き時刻とfpsを有限バッファ・約1秒batchで既存JSONLへ保存する。monotonic時計はRTT付きで同期し、Python画像受取からpaint機会までの推定値とする。撮像時刻・物理表示時刻は取得できず、真の撮影→表示遅延とは区別する。描画前の上書き、非表示、欠落、複数タブ・世代を識別し、推論/QCを変更しない。[仕様](../MacAR/docs/browser-benchmark-logging.md)。

### 2026-10-21：MacAR写真照合の解析入力統一

写真のDINO対象検出・粗検索は幅1280px以下の解析画像、ALIKEDは元写真ROIを既定1024pxで抽出する。bboxは正規化座標、対応UV・K・PnP/QC閾値・CT測定は元写真座標を維持する。登録実写と3DGS参照、再照合と固定参照の検証で共通化し、ライブ処理・地図は変えない。1600/2048pxは比較用に保持する。全条件での速度向上・物理精度同等・メモリ問題の解消は未証明。[仕様と確認](../MacAR/docs/photo-analysis-input.md)。

## 採用している方針

### MacARブラウザのライブMPR（2026-10-16）

Python追跡/最新映像送出はMPR完了を待たない。CT断面内容は同時1件のワーカーで生成し、その世界平面を最新PnP姿勢へブラウザGPU投影する。写真/固定測定の同一画像・姿勢・逆投影は維持する。[詳細と制約](../MacAR/docs/live-mpr-decoupling.md)。以下のThree.js単独ビューアの方針とは区別する。

- **ブラウザ内で処理する**
  - Three.js表示、DICOM／MHA読込、MPR生成をJavaScriptへ集約します。
  - 外部通信を減らせる一方、大規模データではCPU・メモリが制約になります。

- **DICOM患者座標を基準にする**
  - `Image Position Patient`、`Image Orientation Patient`、`Pixel Spacing`を使用します。
  - Three.jsの1 unitを1 mmとして扱い、既定の座標変換は恒等変換です。

- **voxel中心の範囲を使う**
  - Volume中心と物理範囲は`(dimensions - 1) * spacing`を基準にします。
  - MPRサンプル位置と3D空間の表示位置を一致させるためです。

- **MPR中心をカメラ前方に置く**
  - `target = camera.position + camera.forward * MPR距離`で定義します。
  - 通常の既定距離は600 mm、みかん・バナナのデモは300 mmです。
  - `OrbitControls.target`やモデル中心はMPR中心として使用しません。

- **固定断面でも表示位置は視線に追従させる**
  - Axial、Coronal、Sagittalでは断面方向だけを固定します。
  - 断面中心はカメラ前方の注視点へ追従し、CT中央へ固定しません。

- **MPRを3D空間内の実平面として表示する**
  - MPRの`center / u / v / n`と物理FOVをThree.jsへ反映します。
  - サブ画面と3D重畳面は同じ生成画像を共有します。

- **前景透過にはOITを使用する**
  - 対応GPUではWeighted Blended OITで半透明を合成します。
  - OIT非対応環境ではAlpha Hashへフォールバックします。
  - Alpha 0は手前側を切断し、Alpha 1は透過しません。

- **外観モデルはUnlit・両面表示を既定にする**
  - 撮影済みtextureの色を照明で変えず、面方向の不整合による欠落を抑えます。
  - 通常表示ではdepth test／depth writeを有効に保ちます。

- **Reverse-Zと動的near／farを使用する**
  - 対応GPUではReverse-Zを有効にします。
  - 未対応環境では通常depthへ戻し、near／farを表示範囲へ追従させます。

- **3D表現形式を固定しない**
  - 現在はGLB／OBJを使用します。
  - Gaussian Splattingを追加する場合も、座標・カメラ・MPR平面の契約は共通化します。

これらを変更する場合は、表示上の修正ではなく操作仕様または座標仕様の変更として扱います。

### 2026-10-03：照合待ちの点を並行追跡する

ALIKED抽出直後の元画像座標の点を、LightGlueと前景の2D LK追跡へ渡す。照合PASS後に元の点との厳密な対応でXYZを付与し、現在画像で独立PnPと既存QCを行う。未照合の2D追跡は表示姿勢には使わない。最新フレームまでの連続追跡と現在QCが成立した結果は、検索時間だけでは拒否しない。追跡断絶、reset、照合FAILは拒否し、非追跡結果の年齢上限は維持する。CPU追跡とモデルのワーカーを分離する。抽出前の橋渡しは有限の画像履歴を使い、GPU抽出の遅延・消失点の復活・照合誤りは解決範囲に含めない。

### 2026-10-04：登録実写の姿勢候補を領域ごとに評価する

共通cropの8×8領域を最大1票とし、各領域のinlier再投影誤差中央値をRANSAC閾値で正規化して二乗減点する。QC通過候補の点数合計で順位を決め、早期終了と別姿勢の競合判定も同じ支持点数を使う。生inlier数による順位は過去仕様。PnP/QCと3DGS仮想画像経路は維持する。設計判断・制約はMacAR/docs/spatial-pose-scoring.mdに記録する。

### 2026-10-04：対応点補充を物体に対する視点変化で起動する

カメラ回転差と常時の継続補充を、物体中心からカメラ中心への方向差と新たな投影地図区画の増加へ置き換える。点支持が弱い場合の補充と定期全体確認を維持する。新領域は固定3D区画の代表ランドマークを投影して予測し、遮蔽判定と解釈しない。基準は現在画像で確認された姿勢のみ更新し、検索FAILでは維持する。詳細はMacAR/docs/viewpoint-refresh.md。

### 2026-10-05：RC既知姿勢による前処理照合

登録実写の前処理では、RCカメラを固定して先にエピポーラ候補を制限し、ALIKEDの局所descriptor照合から三角測量する。LightGlueは比較方式として保持し、ライブの照合は変えない。既存XYZ/ID、複数画像支持、幾何監査は維持する。仕様・制約はMacAR/docs/known-pose-preprocessing.md。既存地図を自動で置換せず、速度だけで新規地図の精度を保証しない。

620枚の新規前処理は実測9分18秒、保存特徴増補は5分24秒。同じ48ペアの照合平均は約22倍速いが対応数は37.9%。全体倍率・CT物理精度は未確認のため、同条件の実写評価前に既存地図を自動で採用し直さない。[測定条件と結果](../MacAR/KNOWN_POSE_PREPROCESSING_20261005.md)。

### 2026-10-05：写真照合前の未使用MPSメモリ解放

写真入力の初期照合・再照合のworker入口で、MPS同期後に未使用キャッシュを一度解放する。候補拡張は同じ照合内のため解放を繰り返さない。モデルを保持し、CPU・ライブ追跡・照合品質の設定を維持する。18回の反復でdriver確保量の増大を抑え、対応数・姿勢を維持したため採用する。元の抽出20秒が両条件で再現しなかった点、GUI・遮蔽操作を含む長期試験が未実施の点は残る。[条件・結果・反映記録](../MacAR/PHOTO_CACHE_VALIDATION_20261005.md)。
