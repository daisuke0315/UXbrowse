# 研究・開発状況

## この文書の目的

研究構想、実装済み機能、過去の実験結果、将来案を混同しないための状況記録です。数値や主張を外部発表へ使用する場合は、元データ、解析コード、実験条件を別途確認してください。

## 現行ブラウザPoCで実装済み

- 非圧縮、16-bit、単一フレームCT DICOMシリーズの読込
- LOCAL形式の単一MHAボリュームの読込
- DICOM患者座標に基づくVolume構築
- Axial、Coronal、Sagittal、任意斜断面MPR
- 最近傍補間、三線形補間、Window Level／Width
- Three.jsカメラの`eye / target / up`に連動したMPR更新
- OBJ／GLBモデルの表示と基本的な位置・姿勢調整
- OBJ／GLB外観モデルのUnlit表示（GLBのbase color、texture、vertex color、alphaを可能な範囲で継承）
- GLBフォルダ選択時の外部texture相対パス解決
- MPR画像のThree.js空間内プレーン重畳
- MPR平面よりカメラ手前側にあるモデルのshader透過
- CT値しきい値によるMPR画素のalpha透過
- CT座標のX／Y／Z反転とデバッグ情報表示
- デモファントムと小規模なブラウザ単体テスト

## 過去PoCで検討・実装されたもの

- PythonによるDICOM読込とMPR生成
- Unityによる外観モデル操作と断面プレーン表示
- UnityとPython間のWebSocket／HTTP連携
- Unity shaderによる断面手前側の透明化
- RealityCapture、GCP、PostShot等を用いた外観モデル作成手順
- マーカー対応点を用いたCT座標と外観モデル座標の整合
- Procrustes解析、ICP等による誤差評価の試行

これらは過去資産としてリポジトリ内に保存されていますが、すべてが現行ブラウザ版へ移植されているわけではありません。

## 未実装又は現行リポジトリの対象外

- Gaussian Splattingデータの直接読込・描画
- CTと可視光画像を同時取得する撮影装置
- GCP指定、SfM、Bundle Adjustment、GS生成の自動パイプライン
- 撮影からビューア表示までの一貫した座標品質管理
- JPEG、JPEG-LS、JPEG 2000等の圧縮DICOM
- Enhanced CT、PACS、DICOMweb
- 患者情報、検査情報、権限、監査ログの管理
- 多断面の保存、比較、論理合成
- 診断又は治療判断を目的とした医療機器機能

## テスト状況

`tests.html`には次の小規模テストがあります。

- MPR基底ベクトルの単位長と直交性
- world座標からvoxel座標への変換
- Volume中心とvoxel中心範囲
- 最近傍／三線形補間
- Window処理
- Three.jsとVolume間の点・ベクトル変換
- GLBと同一フォルダ／サブフォルダにある外部resourceの相対パス解決
- MHAヘッダ、データ型、異常データの処理

次の統合テストは未整備です。

- 実DICOMシリーズを用いた読込・並び順・HU値の検証
- 斜入DICOM、ガントリチルト、不均一スライス間隔
- 実モデルとMPRプレーンの物理座標一致
- OBJ／GLB材質に対する前景透過shader
- 大規模CTでの応答時間とメモリ使用量
- ブラウザ、OS、GPU間の表示差

## 性能上の状況

MPRは現在CPUで生成し、更新要求は`requestAnimationFrame`と最小更新間隔で集約しています。標準CTで応答が不足する場合は、Web Worker、WASM、WebGL2又はWebGPUを検討します。性能目標を超えた更新は画面ログへ警告されますが、代表的な実データを用いたベンチマークはまだ文書化されていません。

## 精度評価値の暫定整理

プロジェクトメモには、異なる検討に由来すると考えられる次の値があります。

| 記録上の値 | 記録上の文脈 | 現時点の扱い |
|---|---|---|
| 0 ± 0.01 mm | GCPで座標・スケールを合わせた基礎検討 | 評価点、測定方法、試行数の確認が必要 |
| 平均0.899 mm、最大1.207 mm | フォトグラメトリ／外観モデルとCTの比較 | 対応点、補正条件、解析手順の確認が必要 |
| 1.59 ± 0.59 mm | 応用検討、天板のたわみへの言及あり | 補正前後と誤差定義の確認が必要 |
| 0.27 ± 0.12 mm、n=12 | 独立点又はUI統合精度として記載 | 元データとTRE／FRE等の指標定義の確認が必要 |

これらを同一条件の結果として比較又は統合してはいけません。外部発表へ使用する前に、少なくとも次を固定します。

- 評価対象と参照対象
- GCP／FRE／TRE／点間距離／画面上の表示誤差の別
- 座標、スケール、剛体変換、ICP、天板たわみ等の補正条件
- 登録に使った点と独立検証点の分離
- サンプル数、反復数、平均・標準偏差・最大値の定義
- CT測定、マーカー読取、モデル生成、MPR、描画それぞれの不確かさ

数値の再確認が完了するまでは、「医療精度を証明した」「臨床要件を満たした」などの断定には使用しません。

## UX・臨床面で未検証の事項

技術的に断面が連動することと、患者の理解が向上することは別の仮説です。次の評価はまだ必要です。

- 従来のCTビューアと比較した断面位置の理解度
- 説明時間、説明者の負担、患者の主観的理解
- 誤解や過度な安心・不安を生まない表示方法
- 医療者向け操作と患者向け操作の分離
- 対象部位、症例、年齢、空間認知特性による差
- 表示精度が直感性へ与える影響

## 研究上の仮説と実装事実の区別

### 現行コードで確認できる事実

- DICOM患者座標から任意断面を計算する構造がある。
- カメラ前方固定距離の注視点からMPRを更新する。
- MPRプレーンとモデル前景透過を同じ3Dシーンで扱う。

### 今後検証する仮説

- 外観モデル連動UIが非専門家の理解を改善する。
- 撮影段階からDICOM座標を拘束することで、後付け登録より安定した整合が得られる。
- GSの写実性が患者説明又は教育上の価値を高める。
- 同時撮影による時間整合が軟部組織の位置ずれを抑制する。

### 構想・将来案

- CT装置と同期した複数カメラ撮影
- GSを含む外観モデル生成の自動化
- 患者説明、多職種連携、教育、術前計画への展開
- 製品化、共同研究、知的財産、ライセンス等の事業展開

構想は開発方向を示すものですが、実装済み又は有効性確認済みであることを意味しません。
